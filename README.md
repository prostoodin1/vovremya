# Вовремя

«Вовремя» — Android-приложение, которое по расписанию читает локальный Calendar
Provider, находит события во всех выбранных календарях и ставит системные
будильники заранее. По умолчанию сигнал создаётся за 90 минут до начала.

## Что уже реализовано

- чтение Google, локальных и общих календарей через системный Calendar Provider;
- режим всех событий за день или только самого раннего;
- настраиваемое время ежедневной автоматической проверки и уведомление с результатом;
- точный системный будильник с настраиваемыми звуком, вибрацией, мелодией,
  отсрочкой и автоотключением;
- опережение от 0 минут до 14 суток, необязательное крайнее время события и
  горизонт проверки от 7 до 90 дней;
- опциональные события на весь день с отдельным условным временем;
- выбор дней недели и конкретных календарей;
- скрываемый диагностический журнал с состоянием календарей и причиной решения
  по каждому событию;
- восстановление после перезагрузки, смены времени и часового пояса;
- автоматическая проверка и загрузка APK из GitHub Releases;
- светлая/тёмная тема, плавные переходы и анимации;
- экономный режим без постоянно работающего фонового сервиса.

Данные календаря никуда не отправляются: приложение читает их локально на
телефоне. Отдельный OAuth и файл google-services.json не нужны — Google Calendar
должен быть добавлен и синхронизирован в настройках Android.

## Запуск

1. Откройте корень проекта в Android Studio Quail 1 (2026.1.1) или новее.
2. Дождитесь Gradle Sync (JDK 17, Android SDK 36).
3. Запустите конфигурацию app на телефоне с Android 8.0+.
4. При первом запуске разрешите календарь, уведомления, точные будильники и
   полноэкранные уведомления.

Из PowerShell:

    $env:JAVA_HOME = "путь-к-jdk-17"
    $env:ANDROID_SDK_ROOT = "путь-к-android-sdk"
    .\gradlew.bat testDebugUnitTest lintDebug assembleDebug

Debug APK появится в app/build/outputs/apk/debug/app-debug.apk.

## Обновления через GitHub

Укажите репозиторий перед сборкой в gradle.properties:

    githubRepository=owner/repository

Приложение обращается только к публичному endpoint последнего GitHub Release,
сравнивает versionName с тегом вида v1.2.0, скачивает первый APK asset и
показывает уведомление для установки.

Android не разрешает обычному приложению устанавливать APK полностью молча.
Проверка и загрузка автоматические, но пользователь один раз разрешает установку
из этого источника и подтверждает системный экран установки. Каждый новый APK
обязательно должен быть подписан тем же ключом, что и установленная версия.

### Автоматический релиз

Workflow .github/workflows/android-release.yml запускается для тегов v*.
Добавьте в GitHub Actions Secrets:

- ANDROID_KEYSTORE_BASE64 — release keystore в Base64;
- RELEASE_STORE_PASSWORD;
- RELEASE_KEY_ALIAS;
- RELEASE_KEY_PASSWORD.

Затем увеличьте versionCode и versionName в app/build.gradle.kts и отправьте
тег, например v1.1.0. Workflow прогонит тесты/lint, подпишет APK и добавит его к
GitHub Release.

Локально можно скопировать keystore.properties.example в keystore.properties и
заполнить значения. Реальные ключи исключены из Git.

## Как выбирается событие

На выбранном горизонте приложение отбрасывает отменённые и отклонённые
приглашения, затем применяет фильтры календарей, дней и крайнего времени.
Пользователь выбирает будильники для всех событий или только для самого раннего
события даты. Если рассчитанное время сигнала уже прошло, такой будильник не
создаётся. События на весь день можно включить отдельно.

## Энергопотребление

Нет polling или foreground service. Есть один короткий плановый запуск в сутки,
лёгкий ContentObserver во время работы приложения и системные AlarmManager-сигналы. При наличии
разрешения «Будильники и напоминания» время точное; без него Android использует
энергосберегающий приблизительный режим до выдачи разрешения.
